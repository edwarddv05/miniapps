# My SuperApp design direction

## Native redesign — September 2026

The iOS app is the design authority. Expo Go is for the owner's physical iPhone. Keep that development server available. After implementing changes, build a standalone simulator .app with `native-sim --mode build`, review every screen and flow, fix defects, and rebuild until verified. A device .ipa cannot run in an iOS Simulator. Browser previews and Expo Go in the simulator do not approve the final native layout. Preserve Expo Go compatibility for the physical phone.

This redesign replaces the former uniform grouped-list composition. Home is a scrolling day overview: calendar date, next class with its title first, actual in-class progress, remaining agenda, and a seven-day summary of stored classes. Library has separate full-width tool surfaces with a real weekly preview for Horario. The week summary is informational, with weekday and class count in its accessible label.

Tool screens use a compact centered navigation row. Horario has its own day/week heading and native grouped sections with individual class rows. Downloader separates link entry, content/format selection, and a final download action. Settings contains only app-wide options; per-miniapp settings open from each miniapp's title menu. The editor emphasizes the class name and shows recurrence and duration next to the time inputs.

This is a personal app for its owner, who already knows its tools. Do not add instructional cards, appearance descriptions, promotional headings, or explanations of obvious controls. Keep field labels, real content, and actionable errors. Page headers must remain at the top in empty, loading, populated, and error states; the schedule's native List owns the remaining height in every state.

These compositions supersede the older requirements below that prescribe a List for Home/Library, repeat a large tool title below back navigation, or put the download action in the URL field. Retain the functional constraints, data protection, semantic colors, native controls, and accessibility requirements below. The web fallback retains its existing working layout; native screenshots are the visual source of truth.

## Liquid Glass refinement — September 2026

- Hoy shows the date under the large title, not as an oversized numeral. The next-class card states the remaining time (`Termina en` / `Empieza en`); when today has nothing left it names the next class on a following day. `Después` is one solid grouped surface with dividers, followed by the seven-day `Semana` strip.
- Biblioteca's Horario surface carries the same week strip as its real preview; the long-press clear action stays on that surface.
- Tool headers centre the title in its own layer so unequal control groups on each side do not shift it. Peer glass controls sit in one `GlassEffectContainer` (`GlassControlGroup`) so iOS 26 renders them as a single Liquid Glass group.
- Schedule scanning uses `text.viewfinder`, not sparkles, and shows a spinner inside the control while it runs. No continuous symbol animation. The empty schedule uses the native `ContentUnavailableView` with no action, because `+` and scan already live in the header.
- The scan review sheet lists detected classes by weekday and lets the owner deselect any of them. Classes that overlap stored ones start deselected and name the overlap. Importing switches Horario to Semana; no success alert.
- The Gemini key is entered in a `SecureField` and saved only on an explicit action. Saving it from the scan prompt continues the scan.

## Visual identity — September 2026

The app's colour comes from its content, not from chrome. This section supersedes the Palette section below where they differ.

- Grounds are never flat white or black. The page takes a faint tint that follows the time of day: morning `#F3F1EC` / `#12110F`, afternoon `#EEF1F5` / `#0F1217`, night `#ECEBF5` / `#0D0C18`. Cards are `#FFFFFF` in light and `#1B1A26` in dark. Text keeps the semantic `label` / `secondaryLabel` colours.
- The fixed accent is ink indigo, `#4338CA` light and `#A5A1FF` dark (on-accent `#FFFFFF` / `#14123A`). It is used for primary actions, the selected tab and pickers only. The `blue` token name is kept for it.
- Class colours are the signature. On Hoy, the class in progress (or the next one) tints its label, title, progress bar and the day in the week strip, and a blurred glow of that colour sits behind the page, where the glass bars pick it up. Ink is the hue darkened 35 % in light and lightened 40 % in dark to keep text contrast. With no class, the page stays neutral.
- Semana is a timetable grid: one column per weekday (weekends only when used), covering only the hours that hold classes (56 pt per hour). Each class is a block filled with its colour at 20 % (30 % in dark), placed and sized by its hours. A block shows the course code and section ("SI601 V"), or the initials of the name when there is no code ("IO II"), then the room and start time as height allows. Five columns are about 57 pt wide, so full names would break mid-word. Overlapping classes share the column side by side in lanes. Blocks are inset 2 pt on every side (a 4 pt gap between consecutive classes), carry a hairline in their own colour, and faint hour lines run behind them. A block's padding sits inside its fixed frame: padding applied after the frame added 12 pt and made each class overrun the next. Tapping a block opens a native popover anchored to it (a small sheet when the Expo Go build lacks `PopoverView`). The card holds the code and section, full name, a live status ("En curso · termina en…", "Hoy, en…", "Mañana, …", "Lunes, en 3 días"), day, time, duration and room. When the course meets more than once it adds "Esta semana": every session with its room, this one highlighted, and the weekly total. It also flags any class the block collides with. Editing is an icon-only pencil glass button at the card's top right. The popover opens below a block in the upper half and above one in the lower half, never beside it: beside a narrow column there are only about 270 pt. It hangs from the block's nearer edge with its arrow on the facing side (attachment `bottom` with arrow `top` for a card below, `top` with `bottom` for one above), so the arrow touches the class and the card never covers it.
- Classes have an optional Tipo: Teoría (T), Práctica (PRA) or Laboratorio (LAB). It is picked from a menu next to Día, shown after the code ("SI130 U · T") in blocks, rows and the card, and read from a slip's TIPO column. The scanner keeps each row as its own session instead of merging consecutive T and PRA blocks. A course's theory and practice may share hours, so different types of the same course are never a clash (`classesClash`), whether saving, importing or in the card. The card is at most 320 pt wide and never wider than the page, with its padding inside that width. A long press on a block opens the editor directly with a medium haptic. VoiceOver reads the full name and hints at the long press.
- Classes have optional Código and Sección fields next to the name. Typing both together ("GE703U") splits them: the letters after the digits are the section. "Lugar" is labelled "Aula". Code and section show beside the room in Hoy, Después, the day list and the scan review. The scanner reads the CURSO, SEC and AULA columns of enrolment slips.
- Downloader takes the video's colour. The service reports the thumbnail's dominant colour (`ambientColor`) and it becomes the page glow. The link is a floating glass capsule like Safari's address bar, the page is one column without grouped boxes, and saved files appear as pictures (Últimas descargas, Descargas).
- Large titles, the hero class title and the time-left figure use SF Pro Rounded; body text and controls stay SF Pro.
- Scroll edge effect, like the system bars in iOS 26 (WhatsApp's Chats header): page content keeps drawing as it scrolls up under the header (`scrollClipDisabled`), and the header, drawn above it, has a native `ultraThin` material (blur with the least milky tint, closest to the Photos header in iOS 27) masked by a vertical gradient that clears gradually and reaches 40 pt past the header, plus a light scrim of the page ground at the top for legibility; all of it runs under the status bar. Photos uses a true variable blur whose radius grows toward the top; that filter is private, so a fading constant blur is the closest public equivalent. Content blurs progressively toward the top instead of meeting a hard cut. Expo UI 57 exposes no scroll edge effect or navigation bar, so this is composed from `Background` and `Mask`. Those views are recent, so the app checks `expo.getViewConfig('ExpoUI', …)` and, in an Expo Go build without them, falls back to a plain gradient fade of the page ground.
- Neutral circular controls are plain `glass` (no tint); only primary ones are `glassProminent` in the accent. This supersedes the older rule that tinted every circle with a system surface: on the tinted grounds a solid white tint read as a bright disc. Both kinds share the fixed `CIRCLE_CONTROL_SIZE` frame.
- Every React Native view hosted in SwiftUI (`RNHostView`: the video preview, the carousel strip, thumbnails, brand marks) gets an exact width. These views report their own size (a video's natural width), and a flexible `maxWidth: Infinity` frame accepts a size larger than the screen, which widened the Downloader page and cut both edges. In a Form each row's width is fixed, so this only surfaced when the page became a free scrolling column.
- For the same reason, every scrolling page column (Hoy, Semana's grid, Downloader) has an exact width (`usePageWidth`: the screen or 720 pt, minus the page insets), never only a maximum. A text field asks for the width of its text, so a pasted long URL widened the Downloader page until the column was pinned.
- The ambient glow hangs from a zero-size anchor in the page's ground layer, so its 460 pt shape draws past the edges but reports no size. A flexible frame around it accepted that width and pushed the header sideways. The ground layer (tint and glow) ignores the top safe area, so the status bar sits on the page's own colour.

## Fewer boxes — September 2026

- Cards are for real content only: the current or next class, agenda rows, the week strip. Empty, loading and error states sit on the page background (in lists, rows with a clear background and no separator), and lone actions never get a card of their own.
- `Abrir horario` is an icon-only glass button (calendar) in the Hoy header, beside the large title, instead of a wide button inside the class card.
- SF Symbols take their colour through `foregroundStyle`; the `color` prop of Expo UI's Image ignores iOS system colours and falls back to black, which is what turned the colour swatches black.
- While the preview loads, a spinner replaces the play button inside the same glass circle.

## Class colours and Downloader — September 2026

- Classes choose from ten distinct hues backed by iOS system colours (`systemRed` … `systemBrown`), shown as a two-row swatch grid in the editor. They are user metadata on the dot beside a class; they never replace title, time or place. Legacy `slate`, `coral` and `sage` records load as indigo, blue and green, the hues they were shown with. Scanned schedules get one colour per course.
- Downloader's link row shows the detected service's brand mark (YouTube, Instagram, Facebook, X, TikTok; a globe otherwise). An empty field offers Pegar, which pastes and analyses at once. Before any download the screen lists the supported services; afterwards `Recientes` lists saved files, which can be shared again or deleted from the phone.
- Analysis shows a playable preview edge to edge (the thumbnail only when `Ahorro de datos` is on or no stream plays), then title, source mark, author and duration. Posts with several items show a horizontal thumbnail strip.
- The preview player is a native port of the Video.js v10 default video skin (its `react-native` package is still empty, and the web skin renders to the DOM). It keeps the skin's single-row control order (volume, elapsed time, time slider, remaining/duration toggle, settings, full screen). The time slider is drawn YouTube-style: a thin track showing the loaded range from `bufferedPosition` in lighter white and the played range in white, with a dot that grows while dragging. It measures its width in the row (`onGeometryChange`, with an estimate until then), and its drawing hangs from a zero-size anchor so a stale width cannot push the row. Touch is a React Native responder over the track (tap or drag anywhere to seek; VoiceOver adjusts ±10 s): the iOS 26 system slider shows a Liquid Glass lens over its thumb while dragging, even when nearly transparent, and Expo UI cannot hide it. It keeps the skin's controls, its touch gestures (tap toggles controls, double tap on either side seeks 10 s with an accumulating indicator, double tap in the middle goes full screen) and its icon set, rasterised white into `assets/player/` under Apache-2.0. Drawing is SwiftUI: a clear-glass play button and bottom capsule with 35 % dimming over a bare AVPlayer surface. Live Text is off so no OCR button appears on paused frames. The settings menu holds playback speed. YouTube previews play YouTube's own HLS master playlist (the stream Safari uses): H.264 + AAC at every size, fast start, instant seeks, and each dub as an audio rendition switched on the same player. YouTube never marks the original rendition DEFAULT, only names it "… - original", so the player selects it explicitly instead of letting iOS follow the phone's language. The poster only covers the wait for the first frame; rebuffering after a seek shows the spinner over the last frame. If HLS fails, the preview falls back to separate video and audio files, where a second audio player follows the picture and only runs while its clock advances, because AVPlayer reports playing while still buffering. Previews never download to the PC: the phone streams the CDN links yt-dlp resolves (Instagram, X, TikTok and Facebook links already carry sound), and the PC relay is used only when a CDN refuses the phone.
- YouTube dubs: the original language is the default for preview and download. When a video has several tracks, an `Idioma` menu sits with the format controls and switches both.
- Quality labels use the short side of the frame, as players do, so a vertical 1080 × 1920 clip reads 1080p. The download still selects by the real frame height.
- Scrolling closes the keyboard, and so does tapping a static area (page header, post details, the supported-services row) or starting an analysis or download. A tap gesture on the whole Form is avoided because it would swallow taps meant for the field itself and for the pickers.
- Formats follow the content, not a fixed list: video posts offer Video and Audio; YouTube adds Miniatura (its cover art); photo posts and photo items in carousels offer only Foto. The segmented control appears only when there is a choice, and Calidad only for video the site serves in several heights.
- Every saved file must be H.264 or hvc1-tagged HEVC with AAC, in an MP4/M4A whose index sits at the front. VP9/AV1 video plays as sound over black and Photos, WhatsApp and the share sheet refuse it; fragmented MP4 (DASH pieces, piped output) is refused the same way. Quality lists only heights available in a compatible codec.
- Files that already meet that rule download straight from the site to the iPhone (X, Instagram and most single files); files with an undeclared codec are checked with ffprobe first (Facebook's hd/sd are often VP9). When video and audio come apart, the codec needs converting, or the audio arrives as DASH pieces, the PC builds a proper file in a temporary folder while the bar reads `Preparando` with its progress, sends it and deletes it. It never keeps a copy.
- The download action is a compact Liquid Glass capsule (at most 240 × 50 pt) floating above the content and labelled only `Descargar`; format and quality are already visible in the controls above. While downloading, the same capsule becomes a progress bar with percentage and cancel; on success it shows `Guardado` for a moment and returns. It keeps one fixed geometry in every state, with padding inside that frame, so the page never shifts. No separate status row.
- Ajustes holds only what serves the whole app or two or more miniapps: Tema, Datos (respaldo) and the Gemini key (schedule scanner and anime translation).
- Settings that belong to one miniapp live inside it, behind a title menu: a miniapp with its own settings shows its centred title with a small `chevron.down` (like Notes or Files), and tapping it opens a sheet titled with the miniapp's name holding a native Form. Downloader: Ahorro de datos, plus Servidor only in Expo Go (the standalone build downloads on the phone). Metropolitano: Datos del ATU. Horario: Borrar horario (only when there are classes). A miniapp without settings keeps a plain title. No extra header button.

## Anime — September 2026

- Anime is a catalogue client for AniList's public GraphQL API (`anime-api.ts`, no key). The list is a three-column grid of covers. The rating sits on the cover as a small dark capsule (★ 8,4); under it, the title and one line with the kind and year ("TV · 2013", "Película · 2016"), led by a green dot while airing. No episode counts or countdowns on the grid. Everything comes in the same list request; a season count would need each anime's relations and is left out.
- A long press (0.35 s, medium haptic) opens a spotlight card over a dimmed page, not the system context menu and not an enlarged cover. It is as wide as the page (at most 400 pt): AniList's wide banner (or the cover) edge to edge with the status capsule, title and romaji on a dark gradient; then up to three figures side by side (rating, time to the next episode in the anime's colour, kind and year, studio); genres as capsules tinted with the cover colour; four lines of synopsis. It springs in (0.35 s). The banner drifts in a slow Ken Burns pan (9 s, scale 1.04–1.16) and a blurred glow of the cover colour sways under the title inside the dark gradient (6 s); both stop with Reduce Motion. Every padding in the card sits inside its fixed frame: padding after the frame widened the content past the card, pushing the title to the left edge and the synopsis past the right one. Tapping it opens the anime, tapping outside closes it; there are no menu actions. Banner, genres, synopsis and studio come in the list query.
- Loading is a skeleton in the page's real shape (cover blocks with title and meta bars; cover, title and synopsis bars on the detail), pulsing gently unless Reduce Motion is on. A new search or applied filters replace the grid with the skeleton; no spinner in the search field. Rows are lazy and the last one appearing loads the next page.
- Requests are kept to a minimum: search waits 600 ms after typing and needs two letters, every answer is cached in memory for 10 minutes, Kitsu is asked only when AniList finds fewer than 12 title matches, and details and translations are cached too.
- Search is a floating glass capsule like Downloader's link field. Clearing is an `xmark.circle.fill` inside the field, like the system search bar, not a separate glass circle.
- Filters live in a sheet opened from an icon-only header button, which turns accent while any filter is active. The sheet edits a draft and only ✓ applies it (swiping the sheet away discards it); an unchanged draft asks nothing. Applied filters persist on the phone and show as one secondary line under the search. The sheet is not a settings form: every option is visible and one tap away. Orden, Estado, Formato and Géneros are capsule chips that wrap onto rows (solid surface, accent when selected; tapping a selected one clears it). Estado chips carry a status dot (airing green, upcoming indigo, finished grey, paused orange, cancelled red); Formato and Orden chips carry their SF Symbol. Temporada is four tiles with the season's symbol, `Actual` in the heading jumps to the current AniList season, and the year is ‹ 2026 › arrows around a menu of every year ("Cualquier año" when empty), so a distant year is one tap away. Chip rows are packed from an estimated width at the current text size, since Expo UI has no flow layout.
- `Dónde ver` on the detail lists AniList's streaming links as the service's white mark on its brand colour, opening the service. AniList's list is worldwide, not per country. AniList's search only matches whole words, so a typed search also asks Kitsu (which matches word prefixes, "frier" → Frieren; three pages of 20 at once, since Kitsu ranks loosely), fetches those candidates from AniList by id with the same filters, and keeps and ranks everything on the phone only by the main (English) and romaji titles (exact, starts with, word prefix in order…), then popularity. Alternative names and the Japanese title never count: a result must match every typed word in one of those two titles. A chosen order other than Tendencia replaces relevance. Kitsu is optional: slow or down, AniList's results stand alone.
- A title opens on top of the list, so going back keeps the scroll position. The detail's header title stays hidden while the large title beside the cover is visible and fades in, rising 8 pt, between 40 and 120 pt of scroll (`useScrollGeometryChange`, iOS 18+, in tenth steps so scrolling does not re-render every frame). The detail takes the cover's colour as the page glow and its status/next-episode ink. It shows cover and titles, the next episode as a large countdown with its local date and time, Sinopsis, Episodios (airing schedule with Crunchyroll titles where AniList has them; a window of 12 that keeps the next episode in view), Información, and Relacionados (seasons first, as a horizontal cover strip that opens each one).
- Translation never runs by itself: the synopsis heading has an icon-only `translate` button that asks Gemini once, keeps the result on the phone, and afterwards toggles between Spanish and the original. A synopsis translated before opens in Spanish. The Gemini key in Ajustes serves both the schedule scanner and this.

## Mi lista (anime) — September 2026

- The owner keeps three lists: Viendo, Me interesa and Terminados (`anime-library.ts`). They live on the phone with a copy of each anime's list data, shared by Hoy and the Anime miniapp through one store, so neither needs a request to show them.
- Airing data is refreshed with one batched AniList request (`id_in`, 50 per page) for the saved anime that can still change (not finished, not completed), and only when it is stale: an episode that should have aired by now, or six hours since the last refresh; never more than once every 15 minutes. Opening a saved anime's detail updates its copy for free.
- The detail puts three tiles under the cover (Viendo, Me interesa, Terminado; tapping the selected one removes it). While watching, a counter (− 12 / 24 +) keeps the episodes seen; it never passes the episodes already out (an airing series stops at the last aired one, `watchableEpisodes`) and says what is waiting ("2 episodios por ver", "Al día"). Aired episodes in Episodios carry a check when seen; tapping one marks everything up to it (tapping the last seen steps back one). Watching the last episode of a finished series moves it to Terminados with a success haptic.
- Anime opens on the list (titled Anime), which costs no request; a magnifying-glass button in its header opens Explorar, the catalogue with search and filters, and only then is AniList asked. With an empty list Anime opens straight on Explorar; leaving Explorar returns to the list when it has something, otherwise to Biblioteca. Returning to Explorar keeps what it showed without asking again, and browsing pages (no typed text) are kept on the phone for six hours, so reopening the app does not ask either. Covers of saved anime carry the list's symbol in the top-right corner (eye, bookmark, check).
- Biblioteca's Anime row reads Mi lista from the phone: "3 viendo · 2 por ver", "3 viendo · Ep 14 en 3 d", "5 pendientes", or "Catálogo y estrenos" when empty.
- The list page has a segmented Viendo / Me interesa / Terminados (with counts); the chosen tab survives a visit to Explorar. Viendo is a board ordered by what matters. The hero is the next episode among the series the owner is caught up on: a 214 pt card on the anime's banner (or cover) under a dark gradient washed with its colour, with an "Episodio 14" capsule, the countdown at 46 pt heavy rounded in white, the title, and the season bar with the airing moment. Then Por ver (episodes out and not watched, most first), Después (the other caught-up series in airing order) and En curso (series that finished airing). Each is a card tinted from the left with the cover colour: cover, title, then what leads for that state (the number of episodes waiting at 28 pt, the countdown at 28 pt, or the next episode to watch), episode chips instead of a sentence (▶ Ep 13, the next to watch, filled with the anime's colour; 🕒 Ep 14 · Jue 10:26 a. m., the next to air, quiet), and the season bar with "13/26". Series that finished airing lead with progress (12 / 24). The bar's frame aligns left: the stack is only as wide as its widest segment, and a centred frame started the bar partway along. The hero keeps its text legible on any artwork with a four-stop scrim reaching 95 % black at the bottom and soft shadows under the countdown, title and time; times keep a. m. / p. m. and a three-letter weekday ("Jue 10:26 a. m."; one letter would be ambiguous, M is Tuesday and Wednesday). Room comes from the layout instead: in the hero the moment rides in the top capsule ("Episodio 14 · Jue 10:26 a. m.") and the bar takes the full width with the season count; in a card the airing chip drops to its own line whenever both chips do not fit (estimated at the current text size), so it is never cut. Both chips name the episode the same way: "▶ Ep 13", "🕒 Ep 14 · Jue 10:26 a. m.". The season bar has three layers: watched (the anime's colour), out but not watched (the same colour, faint) and still to air (the track), so being caught up or behind reads at a glance. A ✓ marks the next episode as seen (accent when episodes are waiting); caught-up airing series have none, since nothing new is out. Me interesa shows Próximos estrenos first ("Estreno Jue 2 oct, 9:30"), then Disponibles. Terminados are ordered by the date they were finished.
- Hoy gains an `Anime` section only when there is something to say: episodes out that have not been watched ("Ep 13 disponible", "3 episodios por ver") or episodes of what is being watched airing within 36 hours ("Ep 14 · Mañana 9:30"). At most four rows; tapping one opens the Anime miniapp on that anime. Hoy refreshes the list (one request at most) when it appears and when the app returns to the foreground.

## Tarjetas — October 2026

- Tarjetas tracks the owner's credit cards on the phone only (`cards-data.ts` for the cycle logic, tested in `scripts/cards-data.test.cjs`; `cards-store.ts` for storage shared with Hoy and Biblioteca). Money is kept in céntimos, dates as calendar days. A purchase up to and including the closing day (25) belongs to that statement; the statement is paid by the first payment day after it closes (the 12th of the next month). Closing on the 31st uses the last day of shorter months.
- iOS gives other apps no access to the cards in Wallet. A card's face is drawn instead: one of twelve gradients (Grafito, Plata, Oro, Platino and colours) with a chip, or a photo of the card's own art (for example a Wallet screenshot cropped in Photos), copied into the app's documents. The name, the last four digits and the network mark (Visa, Mastercard circles, Amex, Diners) are drawn over it. The art is React Native (`LinearGradient` in `RNHostView`), because Expo Go's SwiftUI build has no gradient fills.
- The page is a Wallet stack: each card shows its name and the open cycle's spending above the next. Tapping one springs it to the top (one spring, response 0.5, damping 0.82) while the others tuck behind it as a deck, scaled and tilted back 8°, their edges still showing. Tapping an edge switches cards; tapping the front card or Back returns to the stack. The page glow takes the card's colour. Sections under the card rise into place one after another (28 pt, 60 ms apart). With Reduce Motion there is no tilt or rise, only a short fade. The card editor's preview turns over once when its design or photo changes.
- A card's page has little text; it is read by shape. The cycle's range sits between ‹ › (back to the first purchase, forward to the last installment). With a budget, a ring winds up to the share used (orange from 80 %, red past 100 %) with the percentage and the budget inside, and a fainter arc runs ahead to where the cycle will close at the current pace (only day-to-day spending is extrapolated; installments and monthly charges are fixed). Beside it, the cycle in soles (dollars included at the bank's soles, or estimated, then prefixed ≈) counts up from zero and rolls on every change; under it a "US$ 20.00" capsule says how much of it is dollars, amber with an hourglass while their soles are missing (tapping it lists those movements), with "a 3,442 ›" beside it opening the rate. Below, the cycle day by day: one bar per day of what was bought, rising in a wave, faint stubs for the days to come and a dot under today, the start date and the closing date with the days left under it. Sliding a finger along it picks a day with a haptic tick per day and filters Movimientos; tapping the day again clears it. The ring and chart are react-native-svg and React Native views in `RNHostView`, animated with React Native's Animated. No daily allowance or explanatory lines.
- Por pagar is a calendar leaf of the payment day (month above, day large, blue, amber within three days, red when late) beside the amount owed in each currency and a ✓ that registers a payment; a paid statement shows as one line that can be tapped to undo it. Then two tiles side by side, label above a figure with two decimals, stretched to the taller one (the row is sized to its content and each tile fills its height, no fixed frame): Disponible and Cashback, neither with a bar (tapping Cashback unfolds the categories). Then a bar in category colours and a chip per category with its amount (and limit, coloured as it fills); tapping a chip filters Movimientos. The active filter shows as a capsule beside the heading that clears it. A movement leads with its own currency; a dollar one shows its soles under it, or "Sin soles" in amber.
- Without a selection the page lists Por pagar across cards (calendar leaf, amounts, card) and the latest purchases.
- A purchase has amount, description (defaulting to its category), one of thirteen categories, card, date, and either installments (1–36, spread over consecutive statements, the last one taking the remainder) or Mensual (charged every month on the same day until stopped; stopping keeps past charges). The card list shows each card's cashback for the chosen category and stars the one that returns the most. A line says when it is paid and the cashback it earns. Crossing 80 % or 100 % of the budget ends the save with a warning haptic instead of the success one.
- Hoy gains a Tarjetas section only when a statement is due within seven days (or late) or a card is past 80 % of its budget. Biblioteca's row reads "S/ 1,240 este ciclo · pagar en 11 días".
- Storage that cannot be read shows an error with Reintentar and blocks writes; a failed save rolls the change back.
- Purchases are in Soles or Dólares (a segmented choice under the amount). A dollar purchase keeps the soles the bank converted it to in En soles, optional, typed when the statement shows them. Until then an exchange rate estimates them (the field's placeholder shows the estimate, "≈ S/ 75.00"), and estimated figures carry "≈" in movements, Disponible and Cashback; the hero's dollar capsule stays amber with a line "≈ S/ 75.00 a 3,756" that opens the rate. The bank applies its own selling rate on the day it processes the charge, which no public source gives, so the rate is only an estimate and the bank's soles always win. A card marked Estado de cuenta bimoneda bills dollar purchases in a dollar balance: statements owe soles and dollars separately and payments are registered per currency (Pago total, Solo S/ …, Solo US$ …, Otro monto in either). On other cards a dollar purchase is billed in soles once they are known, and in dollars until then. The credit line, budgets, category limits and cashback are in soles, estimates included; dollars with neither the bank's soles nor a rate are shown apart. A partly paid dollar balance frees the line by its share of the soles it cost.
- The exchange rate opens from a row under the overview (shown once there are dollar purchases) or from the hero's estimate line. Automático takes the market rate from open.er-api.com plus an optional bank margin (%); it is fetched at most once a day, only on opening Tarjetas while some dollar purchase lacks its soles, and a failed attempt is not repeated until the app restarts. Actualizar ahora asks on demand. Manual is a rate typed there and never changes by itself. The sheet edits a draft with the resulting rate large at the top; ✓ applies it.
- Expo UI's `Animation.delay()` changes the animation it is called on, so delayed animations are built fresh each time.

## Product

My SuperApp is a quiet personal home for small, focused tools. The shipped tools are Horario, a weekly planner for seeing and editing recurring classes or commitments, and Downloader, a compact downloader that runs yt-dlp inside the standalone app and falls back to the PC service in Expo Go.

The iOS surface is implemented with `@expo/ui/swift-ui`: `App.ios.tsx` holds the tabs, Hoy, Miniapps and Ajustes, and each miniapp lives in `screens/` (`schedule`, `downloader`, `anime`, `transit`, `cards`) on top of `screens/shared.tsx`. `ios/` is the generated native project. Its `Host`, `TabView`, `Form`, `List`, `Button`, `TextField`, `DatePicker`, and `BottomSheet` map to native SwiftUI. `App.tsx` remains the React Native web preview.

## Navigation

The primary shell has three destinations: Inicio, Miniapps, and Ajustes. Miniapps is plural because the shell holds more than one focused tool. The shipped tools are Horario and Downloader. Unbuilt tools do not appear as interactive cards.

Inicio opens a screen titled Hoy. Its job is to show the current or next remaining class, followed by the rest of today's agenda. Finished classes never appear as the next class. Use one explicit Abrir horario action and avoid repeating it on every preview row. A day with completed classes differs from a day with no classes.

Miniapps owns one local destination: library, schedule, or downloader. Keep that state independent of the selected tab and of schedule storage availability. Downloader remains reachable if the schedule fails to load. Only the schedule's current flow offers storage recovery.

## Visual character

Use an Apple-native, calm, translucent interface. Liquid Glass belongs to functional chrome and primary actions, not every content surface. The schedule itself should remain crisp and readable over a quiet content background.

## Palette

- Native iOS backgrounds and text use semantic system colors (`systemGroupedBackground`, grouped surfaces, `label`, `secondaryLabel`, `separator`). Do not replace them with fixed approximations.
- Slate: `#24324A` in light mode, `#AFC2E0` in dark mode.
- Blue: `#0A66E8` in light mode, `#7DB0FF` in dark mode. Prominent labels use white in light mode and `#14161C` in dark mode.
- Red remains reserved for destructive actions such as deleting the schedule; it is not the app accent.
- Keep the native host, UIKit appearance, and status bar in the same selected appearance. System is the default.
- The web preview has its own React Native palette; it is not evidence of native rendering.

## Navigation and copy constraints

Keep the tab bar available within Horario. Opening Horario from Inicio selects Miniapps; returning to a tab preserves its local destination. Do not add a second link to Miniapps on Inicio.

Use short functional labels. Omit promotional subtitles, descriptions of obvious navigation, unavailable-tool placeholders, and nonfunctional settings. Familiar add/create actions show only `+`, and back actions show only `<`; keep their full names in accessibility labels. Keep one visible control per action within the same screen context; do not repeat an action in both the header and the empty state. Destructive schedule clearing lives in the Horario title menu and, as a shortcut, on a long press of the Horario miniapp card; both confirm before execution. Ajustes contains only app-wide options. Empty states may offer a relevant action without explaining the whole app.

Downloader uses a two-step flow: one URL field with a prominent icon-only `Analizar` action, followed by a compact result with the discovered title, source, user, description and duration, the available video count, quality options returned by the service, the native segmented choice between Video and Audio, and a prominent icon-only `Descargar` action. Visible copy stays functional and compact; the controls should carry the explanation. The iOS client does not embed Python or yt-dlp; it calls the local Windows service in `downloader-service/`, which analyzes the link before extraction and returns a file for the iOS share sheet. Keep service failures concise and actionable; do not present backend implementation details in the normal UI.

## Typography

Use the system sans-serif from SwiftUI on iOS. Native text styles keep Spanish labels readable and respect Dynamic Type without imitating a developer tool.

In stacked form rows, field labels and user-entered values must not share the same visual treatment: labels use one consistent role across the form, values use the primary body style, and placeholders remain muted. Distinguish labels from values with weight, size, spacing, or field structure; do not make only a subset of labels gray. This distinction must survive light/dark mode and Dynamic Type.

Meaningful SF Symbols also use Dynamic Type text styles. Schedule rows stack when width or text size makes side-by-side content crowded. Do not set fixed widths on time or weekday text.

## Composition

Use a shared top title area, a `Hoy` view that reads the current day directly, and a single readable agenda column. `Hoy` and `Semana` are two views of the same recurring schedule. Do not add a day selector to the `Hoy` view. Semana groups every class by weekday; it must not hide all but the first class. Avoid dashboard grids. The schedule is the focal point. Supporting actions stay close to the schedule and use labels when an icon alone could be ambiguous. Peer controls in the same navigation row share a vertical centerline; do not split back and create controls across different rows.

Design Read: a quiet personal utility for students and people managing recurring commitments, in a native grouped-list language, with ENERGY 2 / RHYTHM 2 / MOTION 1. The focal point is the next useful action, not decorative surface area.

Miniapps uses one native grouped List, titled Biblioteca, containing real tools. Agenda uses List and Section. Ajustes uses a Form with an inline theme picker, giving each option its own readable row. These containers own separators, grouped surfaces and scrolling. Do not wrap each native row in a second rounded card or draw an extra border around the list. The schedule rows use a small color marker only as user-selected metadata; title, time, and location always carry the meaning. The web preview mirrors this structure so it can validate behavior without becoming a separate visual product.

Glass is limited to the tab bar and functional controls such as back, add, save, and download. Content rows and form surfaces remain solid system-like surfaces so the timetable stays crisp and readable.

Sheet action rows use one shared `SHEET_ACTION_INSET` for leading, trailing, top, and bottom edges around peer controls. Equal guides are the baseline; a different inset needs a deliberate platform or safe-area reason and must be checked at the rendered point size. All peer circular controls use the shared `CIRCLE_CONTROL_SIZE` token; the current value is 44 pt, matching the iOS default hit target.

## Liquid Glass rules

- Use the native SwiftUI `TabView` for the bottom tab bar and SwiftUI `buttonStyle('glass')` or `buttonStyle('glassProminent')` for functional actions on iOS 26+.
- Use native glass button styles for primary actions and back controls. Library and agenda rows remain solid. Back controls show only a leading `chevron.left` (`<`) and keep the destination in their accessible label.
- Icon-only native glass buttons use a shared fixed icon layout inside the shared `CIRCLE_CONTROL_SIZE` frame; circular peers keep the same prominent glass variant and primary emphasis comes from tinting `+` and `✓` blue. Neutral controls use a system surface tint. Avoid adding extra padding to the label because the native style owns its insets.
- Never place an opaque circle underneath a native glass button or add a separate glassEffect to it. The button style owns its surface and interaction.
- Use the bordered SwiftUI fallback on older iOS versions.
- Keep schedule rows and empty states on solid or standard material surfaces so the timetable remains legible.
- Do not simulate native glass with opaque blur layers or decorative panels.

## Editing and data states

The editor keeps icon-only `×` and `✓` actions above the scrolling form, with full accessibility labels. Present it first at a medium detent and allow expansion to large when the form or keyboard needs room. Keep the action row and form on the same semantic background; use the system presentation material and readable content surfaces. Confirm discarding changed fields, prevent concurrent writes, and keep the draft on save failure.

Keep the editor title between the two actions. Split fields into Clase (name), Horario (day and times), and Detalles (location and color). This separates the required scheduling decision from optional metadata without extra explanatory copy. Disable all editable controls during saving.

Downloader uses separate Enlace, Contenido, and Formato groups. Reveal the latter two only after analysis succeeds, and lock the URL and format during a request. Show progress while analyzing or downloading. An invalid URL receives Spanish recovery text, never the platform parser's technical error. Switching tabs on the web preview preserves its current form and request.

## Shared structure and rationale

- `ui-structure.ts` owns content width, page and sheet insets, circular control size, group radius and miniapp destinations. Shared values keep iOS and the preview aligned.
- `PageNative` owns the common title and action alignment; `List` and `Form` own native content layout. The installed Expo UI 57 API does not expose NavigationStack or navigation toolbar components; the header remains composed from SwiftUI views and buttons. Native edge-swipe back and large-title collapse are not implemented by this shell.
- `AgendaContentNative` and `AgendaContent` give home previews, daily agenda and the week one consistent time/title/location hierarchy.
- `schedule-data.ts` owns the stored entry type, validation and today's remaining agenda calculation. `use-current-time.ts` refreshes that calculation while open and when the app returns to the foreground.
- System typography serves a reading utility and adapts to Dynamic Type on iOS. Blue identifies primary actions, while the agenda stays neutral. SF Symbols retain their conventional meanings: calendar for recurring classes, download arrow for downloading, and standard action symbols.
- Grouped solid surfaces make related content readable; native glass belongs to the functional layer. Spacing separates sections at 20–24 points and related information at 4–16 points. ENERGY 2 / RHYTHM 2 / MOTION 1 remains the design direction.

Loading or invalid storage must not appear as an empty schedule. Show a recovery action and block schedule writes until existing data has loaded successfully. Errors from deleting or changing preferences belong in the current flow.

## Motion

ENERGY 2 / RHYTHM 2 / MOTION 1. Use motion only for tab selection, sheet presentation, and confirming a saved class. Avoid animation on every list row or keystroke. Respect reduced-motion settings where the platform exposes them.

Do not add a generic haptic to every button or navigation action. Keep explicit feedback for meaningful outcomes and actual selection changes; let native controls handle their own interactions.

## UI review invariants

When a UI correction reveals a reusable problem, promote it to a shared token or invariant and apply it to native and fallback surfaces. Review repeated geometry, alignment, role hierarchy, duplicate actions, semantic color usage, and redundant state copy before considering a screen finished.
